# ADR-NIUV-0001: niuv は Nim・Gleam・WASM のビルドの道具である

**Status**: proposed
**Date**: 2026-10-16
**出どころ**: `fukai/docs/build-and-delivery.md` の 1.1 章（B1〜B7）と 4.2 章（持つ物・持たない物）。jasagiri の決定（2026-10-16）: ビルドは `foundation/niuv`、配るのは `fukai/delivery`（この ADR の範囲外）
**仮説の層**: 実装。支配軸: 整合性（既に決まった線に新しい仕組みを足さない）。二次条件: 実現可能性（技術。規則 NIV-17 を 2 か所のビルドで確かめる）

## 文脈

旧 niuv は Nim の仮想環境の管理だった（jj の `f06a84e1` に残してある）。fukai は Nim・Gleam・WASM を組み合わせてビルドする道具を必要としているが、現状は手書きの `nim.cfg` と `scripts/build.sh` の配線に頼っている。依存の依存を呼び手が書き、BearSSL の版は `--path` で人が固定し、Gleam は深さの違う相対パスで兄弟を指す。この ADR は、その配線を宣言・解決・ロック・ビルド・目録・門に置き換える道具の規則を決める。

## 規則

宣言（`niuv.toml`、パッケージごと）

- **NIV-01** 宣言は `[package]` に `name`、`version`、`license` を必須で持つ。名前は英数字・`-`・`_` だけ、版は `x.y.z`、`license` は空でない文字列。必須項目の欠落、型の違い、知らない節・キーは、場所（ファイルと節）を示して断る。
- **NIV-02** `[nim]` 節は `src`（探索パスの根。既定 `src`）、`flags`（このパッケージを根にビルドするとき `nim c` に渡す旗）、`[[nim.bin]]`（出す実行ファイル。`name`、`main`、`flags`、`sealed`）を持つ。`name` は 1 つの宣言の中で重ならない。`sealed` の既定は偽。
- **NIV-03** `[gleam]` 節は `root`（Gleam のパッケージの根。既定 `.`）と `sealed` を持つ。
- **NIV-04** `[wasm]` 節は `entry` と `sealed` を持つ。niuv は宣言の形を読んで検証するだけで、WASM のコンパイル手順は持たない。ビルドは「WASM は宣言のみ。ビルドしない」と報告し、成果物には数えない。
- **NIV-05** 依存は `[dependencies]` に書く。`workspace`（作業場の中のパッケージ名の配列）と、`[dependencies.external.<名前>]`（外のもの。`source`、`version`、任意の `src`、任意の `license`）。外の依存の `version` は完全な `x.y.z` だけを受ける。`license` を書かない外の依存は、SBOM では `NOASSERTION`、封じる印の成果物の閉包では NIV-20 で断られる。
- **NIV-06** `[package]` の `root` は、この宣言が指すパッケージの根を宣言の置き場からの相対で示す。宣言を持たない既存のパッケージを作業場から指すために使う。`src`、`main`、Gleam の `root` などの相対パスは、この根から数える。

作業場（`niuv.workspace.toml`）

- **NIV-07** 作業場は `members`（宣言のあるディレクトリの配列。作業場ファイルからの相対）と、ツールの節 `[tools.<nim|gleam|erlang>]`（`version`、任意で `via = "mise"`）、外の依存の探し場所 `[external] roots`（配列）を持つ。名前から場所を引く表になる。同じ名前のパッケージが 2 つあれば断る。宣言が無い、または読めないメンバーは断る。

解決

- **NIV-08** 解決は、根のパッケージから `workspace` の名前の依存をたどり、閉包を、依存が先・名前順の決まった順序で返す。作業場に無い名前、循環は断る。外の依存は、探し場所の中に取得元と版が一致するディレクトリが無ければ断る。
- **NIV-09** 閉包に同じ外の依存の名前が 2 つの版（または 2 つの取得元）で来たら、どの 2 つのパッケージが何を要求したかを示して断る。例: BearSSL 0.2.6 と 0.2.13。
- **NIV-10** 版の範囲（`>=`、`^`、`~`、`*`、`,`）と SAT による解決は持たない。範囲の記法は NIV-05 で断る。理由: 作業場の中は 1 つの版しか無く、外の依存は固定するだけだから。

ロック（`niuv.lock`）

- **NIV-11** `niuv lock` は `niuv.lock` を書く。中身は、ツール（版と実行ファイルの SHA-256）、作業場の中のパッケージ（作業場からの相対の場所と中身のハッシュ）、外の依存（取得元、版、中身のハッシュ）。中身のハッシュは、宣言したソースの木のファイル名と SHA-256 の並びの SHA-256 で、ビルドの出力・キャッシュ・`.git` は含めない。同じ入力からは同じバイト列を書く。ロックは作業場の全メンバーを覆うので、作業場は外の依存の名前ごとに 1 つの固定だけを持つ（メンバーが別々の閉包で同じ名前を別の版に固定していても `niuv lock` は断る）。
- **NIV-12** `niuv build` は、ロックが無い、または閉包のどれかの場所・中身のハッシュがロックと違うとき、断る（`niuv lock` を促す）。
- **NIV-13** `niuv build` は、実際のツールの版または実行ファイルの SHA-256 がロックと違えば断る。`via = "mise"` は実行ファイルを見つけるためだけに使い、ロックとの照合は同じにする。

Nim

- **NIV-14** Nim のビルドは、閉包の探索パスを `--path` の旗で渡し、`--noNimblePath`、`--skipUserCfg`、`--skipParentCfg`、`--skipProjCfg` で nimble の暗黙の探索と周りの設定ファイルを使わない。宣言に無い依存の import は、解決されずにコンパイルが失敗する。
- **NIV-15** `niuv build <パッケージ>` は宣言した各 `[[nim.bin]]` をビルドし、`--out` の下に名前で置く。`--out` には成果物と目録・SBOM だけを置き、コンパイラの作業場（nimcache）は置き場の根の下に、出力先と bin ごとに分けて置く。コンパイラが失敗したら、その出力を付けて失敗を返す。

Gleam

- **NIV-16** Gleam のコンパイルは、niuv が閉包の順（依存が先、深さ優先、名前順）に、パッケージごとに `gleam compile-package --target erlang --package <ソースの場所> --out <置き場>/lib/<名前> --lib <そのパッケージの依存だけを指す置き場>/libs/<名前> --no-dev` を呼んで行う（2026-10-17、fukai roadmap 0.1 章 121。それまでは閉包を置き場に写して `path` を書き換え、根で `gleam export erlang-shipment` を呼んでいた）。ローカルのパッケージは今ある場所のまま（写さない、書き換えない）読み、各パッケージが見る `--lib` には、その `gleam.toml` の `[dependencies]`（`path` と Hex）から推移的にたどれるパッケージだけを（シンボリックリンクで）置く。宣言していないパッケージの import は `Unknown module` で断られる。Hex のパッケージは、根の `manifest.toml`（gleam 自身のロック）の `source = "hex"` の行（版、`outer_checksum`、`otp_app`、`requirements`）を**読むだけ**で（版の範囲は照らさない。この版を作る）、gleam の Hex の写し（`<写し>/<OUTER_CHECKSUM>.tar`）の SHA-256 が `outer_checksum` と一致することを niuv が確かめてから、`tar` で置き場の `src/<名前>/` に展開して同じように compile-package にかける。写しに無い、checksum が違う、ロックが持たない、アーカイブの中に `/` 始まりや `..` の名前がある、シンボリックリンクがある、は断る。`gleam` に依存の解決はさせない: gleam 1.19.1 は、`path` 依存を持つパッケージのまっさらな作業場（`build/packages/*.config_fingerprint` が無い）で `manifest.toml` を古いとみなし、ロックされていても Hex のレジストリへ版を問い合わせるため、網のないゲストで落ちる（NIV-31）。出荷するのは、閉包（dev 依存を除く）の各パッケージの `ebin/*.beam`。`gleam export erlang-shipment` が根に足す `<アプリ>@@main` の入口モジュールと起動スクリプトは出さない。`gleam.toml` の `path` 依存（相対ならそのパッケージから数え、絶対ならそのまま）が、閉包の Gleam パッケージのどれとも合わない、または宣言された場所と違う所を指すときは、断る（`[dev-dependencies]` の `path` は見ない）。
- **NIV-17** 決まったバイト列: 置き場は入力（ツールの版と実行ファイルの SHA-256、閉包の各 Gleam パッケージの中身のハッシュ、Hex のアーカイブの checksum）のハッシュで名付けたディレクトリで、毎回作り直す。`gleam` は `ERL_COMPILER_OPTIONS=deterministic` の下で呼び、利用者の環境の同名の変数は上書きする。同じ入力を、作業場の場所も置き場の根も違う 2 つの場所から別々にビルドして、出荷される全 `.beam`（Erlang の FFI と Hex のパッケージを含む）の SHA-256 が一致する。**約束は niuv の道の中だけ**: 同じ依存の組から作った `.beam` は一致するが、`gleam export erlang-shipment` で作った同じ名前の `.beam` とは一致しない物がある（`debug_info` と `Docs` の欄にある型変数の名前が、gleam が 1 つのプロセスで何を先に読んだかで決まるため。コードの欄は同じ。fukai/agent の閉包の 53 モジュールのうち 10。2026-10-17 測定）。
- **NIV-18** 目録は成果物ごとに名前・種類（`beam` / `nim-child` / `wasm`）・SHA-256・大きさを持ち、`nim-cbor-det` の決定的 CBOR で書き、ビルドの出力先に `niuv.manifest.cbor` として置く。配置は `{1: 形式の版 (1), 2: パッケージ, 3: 版, 4: [{1: 名前, 2: 種類, 3: SHA-256 (32 バイト), 4: 大きさ}]}`、並びは種類・名前の順、場所は載せない。署名はしない。同じ成果物からは同じバイト列。Future: Gleam の `.app` ファイルは目録に入れていない（`.beam` だけ）。
- **NIV-19** SBOM は閉包の各パッケージの名前・版・ライセンスを CycloneDX 1.5 の部分集合（JSON）で出し、ビルドの出力先に `niuv.sbom.cdx.json` として置く。作業場の中のパッケージは `[package] license`、外の依存は宣言の `license`（無ければ `NOASSERTION`）、niuv が Hex の写しから展開した Hex のパッケージはそのパッケージ自身の `gleam.toml` の `licences` から取る。名前順で、同じ入力からは同じバイト列。
- **NIV-20** ライセンスの門: `sealed` 印の成果物を出すビルドで、その言語の閉包（Nim の bin なら Nim のコードを出すパッケージと外の依存、Gleam なら Gleam のパッケージと Hex のパッケージ）に GPL-3.0 / LGPL-3.0 / AGPL-3.0（SPDX の `-only`・`-or-later`・`+` の綴りを含む）が入れば、パッケージ名とライセンスを示して断る。ライセンスが分からない（外の依存で `license` が無い）パッケージが入るときも断る。`OR` の式でも、v3 の copyleft が 1 つでも並んでいれば断る（どちら側を取るかは人の判断で、門の仕事ではない）。`sealed` でない成果物では門は開いている（SBOM には載せる）。宣言で分かる分は、どのコンパイラも走る前に判定する。Hex のパッケージは取得後に判定する。

そのほか

- **NIV-21** niuv は腐海の Nim の子としても呼べる: `niuv child` は `nim-frames` の枠（`runChild`）で 1 つの頼み（ビルド）を受け、目録のバイト列を返す。頼みは `{1: 種類（1 = ビルド）, 2: 作業場のファイル, 3: パッケージ名, 4: 出力先, 5: 置き場の根（任意）}`、返事は `ok {1: 目録のバイト列}`。失敗の番号は nim-frames の共通の番号: 頼みの形の誤りは malformed、知らない種類は unknown-kind、作業場・パッケージが無いのは not-found、宣言・ロック・ツール・ライセンス・版の衝突は refused、コンパイラや入出力の失敗は io。
- **NIV-22** コマンドは `lock`、`check`、`build`、`child` だけを受ける。それ以外（`venv`、`activate`、`install` など）は、使い方を示して断る。
- **NIV-23** Gleam の成果物の `.beam` は、出力先の `beam/<アプリケーション>/<モジュール>.beam` に置く（アプリケーションは shipment の中のディレクトリ名）。目録（NIV-18）は場所を載せないので、配る側はこの配置と目録の名前・SHA-256 で成果物を探す。

## 採らなかった案（コメントに書かない設計判断の置き場）

- **fukai の `scripts/build.sh` と同じバイト列にそろえる**: niuv の出力は、同じ引数の `nim c`（設定ファイルを読まず、探索パスを旗で渡す）と一致することを確かめた（`fukai/store` と `fukai/keeper` の 4 つ）。`build.sh` の出力とは一致しない。理由は 2 つ。(1) nimcrypto・results が nimble の lazy な探索（`pkgs2`）で見つかると、モジュールの名前が `@nnimcrypto-0.7.3-<hash>@s…` になり、`--path` で指すと `@pnimcrypto@s…` になる。シンボル名が変わるので、実行ファイルが違う。(2) 設定ファイル（`nim.cfg`）を読むとコンパイラのファイル番号が 1 つずれ、`_Dl_<番号>_` のシンボル名と `LC_UUID` が変わる。そろえるには nimble の暗黙の探索を許すしかなく、NIV-14（宣言に無い依存は見つからない）に反する。そろえない。違いが名前だけであることは、2026-10-16 に `--genDeps:on` で両方の依存の一覧を出して確かめた: `sealer_child`・`blob_child`（174 件）、`key_child`（154 件）、`fukai_key`（160 件）で、コンパイルしたソースの組と各ファイルの SHA-256 が一致し、外の依存の置き場（BearSSL 0.2.13 の pkgcache、pkgs2 の nimcrypto 0.7.3・results 0.5.1）も同じ。旗も宣言と `build.sh` で同じ。

- **nimble に任せる**: nimble の lazy な pkgs2 は 0.2.6 しか持たず、BearSSL のように固定した版を別の場所から使うには `--path` の手書きが要る。nimble の暗黙の探索は、宣言に無い依存が通ってしまう（NIV-14 が閉じる）。
- **`nim.cfg` を生成する**: 設定ファイルは周りのディレクトリの設定と重なり、どの旗が効いたかが見えない。旗は引数で渡し、ロックと目録に結ぶ。
- **版の範囲と SAT**: 旧 niuv が持っていた。作業場の中は 1 つの版で、外の依存は固定する。範囲が要る使い手が現れるまで作らない。
- **（採った、2026-10-17）`compile-package` で 1 パッケージずつ niuv が順に呼ぶ案**: 当初は Hex の取得・展開・検証を niuv が持つ車輪の再発明として採らず、`gleam.toml` の `path` を書き換えた写しを置いて `gleam export erlang-shipment` を呼んでいた。K4-3 で、その道は網のないゲストで通らないと分かり（NIV-16）、採った。取得は持たない（Hex の写しを読んで checksum を確かめるだけ）。
- **`gleam` を 2 回流して指紋のファイルを書かせる**: 1 回目は Hex への問い合わせで落ちる（その副作用が目的）。落ちることを前提にした手順は、エラーを握り潰さない原則と相容れない。指紋は gleam の内部の値で niuv が自分で書けない。採らない。
- **`gleam export erlang-shipment` の `.beam` と同じバイト列を、新しい道でも出す**: 型変数の名前の食い違いは gleam の内部のカウンタに由来し、`compile-package` の呼び方からは変えられない。合わせるために `debug_info` を落とすと、コードの欄の同一性を測る手がかりも失う。採らない（NIV-17 の約束は niuv の道の中だけ）。
- **外の依存の取得（git clone、hex）**: B7（網なしで 1 台で動く）に反する。探し場所に置かれた物を、取得元・版で選び、中身のハッシュで固定する。取得は `nimble` や人に任せる。

## 影響

- 各パッケージのリポジトリに `niuv.toml` を置く。宣言を持たない既存のパッケージは、作業場から `root` で指す。
- 旧 niuv の機能は消える。消した物と読み戻し方は `docs/removed-2026-10-16.md`。

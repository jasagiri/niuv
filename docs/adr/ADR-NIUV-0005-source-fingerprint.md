# ADR-NIUV-0005: niuv は自分のソースの指紋を持ち、古い実行ファイルはビルドを断る

**Status**: 決定の記録なし。司会の指示（2026-10-29「古い実行ファイルが黙って使われないように。持ち主として決めて使い手に伝えて」、同日「古さを終了の値で答える口を」）で、niuv の持ち主が決めて実装した
**Date**: 2026-10-29
**出どころ**: 社内の OS の報告（2026-10-29）: `foundation/niuv/build/bin/niuv` が e7202e43（`-w` を外した）より前の実行ファイルのままで、社内の OS の台本はそれを使っていた。使い手は、ソースにもう無い規則でビルドしていた。
**仮説の層**: 実装。支配軸: リスク・不確実性（ビルドの規則が、ソースと実行ファイルの 2 か所にずれて在る）。想定する失敗: 早合点（ビルドが通ったことを、今の規則で作ったことと等価視する）。

## 規則

- **NIV-46** niuv の実行ファイルは、組んだときの自分のソースの指紋（`src/` の `*.nim`・`*.c`、`nim.cfg`、`config.nims` を、名前の順に、名前・長さ・中身で並べた SHA-256）を持つ。`niuv --version` は版と指紋と、組んだ場所のソースと一致するかを出す。`--version` と `--help` 以外のコマンド（`lock`・`check`・`build`・`child`・`wasm`）は、組んだ場所のソースの今の指紋が違えば、作り直しの命令を示して断る。組んだ場所にソースが無ければ（写した実行ファイル）確かめられず、そのまま動き、`--version` がそう言う。

- **NIV-47** 古さは終了の値で答える（呼び手が文面を比べて分けないため。失敗の文面は契約ではない）。`niuv --version --check` は、ソースと一致なら 0、古ければ 3、組んだ場所にソースが無ければ 4 で終わる。`--version` だけなら古くても 0。NIV-46 で断るコマンドも 3 で終わる。ソースを読めないときは 1。

実装は `src/niuv/fingerprint.nim`（組むときに `staticRead` で同じ関数に通す）と `cli.nim`。E テストは `tests/unit/test_fingerprint.nim`。

## 採らなかった案

- **使い手の台本が毎回 niuv を作り直す**: 作り直しに数十秒かかり、テストの道ごとに払うことになる。
- **使い手の台本が指紋を比べる**: 比べ方が使い手ごとに写される。niuv 自身が断れば、どの使い手も何も持たなくてよい。
- **jj の commit の ID を埋める**: 作業中の（コミットしていない）変更を見分けられない。
- **古いときに注だけ出して続ける**: 成功したビルドの注は読まれない。断る。

## 範囲の外

- `nim.cfg` の `--path` が指す兄弟のリポジトリ（nim-cbor-det、nim-frames）の変更は、指紋に入らない。

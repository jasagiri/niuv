# niuv Enhanced Features

このドキュメントでは、niuvに追加された拡張機能について説明します。これらの機能により、PATH問題の解決とプロジェクトセットアップが自動化されます。

## 🔧 自動インストール機能 (`install-self`)

### 概要
PATH問題を自動解決してniuvをシステムに堅牢にインストールする機能です。

### 機能
- **マルチプラットフォーム対応**: Linux、macOS、Windows
- **PATH問題の自動解決**: `dirname`、`mkdir`などのコマンドが見つからない問題を解決
- **堅牢なラッパー作成**: 環境に依存しない実行環境を提供
- **シェル自動検出**: bash、zsh、fish、tcshを自動検出
- **設定ファイル自動更新**: PATH設定を自動追加

### 使用方法

```bash
# 基本インストール
niuv install-self

# 強制再インストール
niuv install-self --force

# インストール状態確認
niuv install-self --status

# ヘルプ表示
niuv install-self --help
```

### インストール方法の自動選択

1. **~/.local/bin** (最優先)
   - ユーザー専用ディレクトリ
   - 管理者権限不要
   - 標準的なPATH設定

2. **~/bin** (代替)
   - 従来からのユーザーディレクトリ
   - 自動でPATH設定に追加

3. **手動設定** (フォールバック)
   - 自動インストールが失敗した場合の手動手順を表示

### 堅牢なラッパーの特徴

作成されるラッパースクリプトは以下の問題を解決します：

```bash
#!/bin/bash
# niuv wrapper - auto-generated by niuv auto-installer

# 標準的なPATHを設定してコマンド不足を回避
export PATH="/usr/bin:/bin:/usr/sbin:/sbin:/usr/local/bin:$HOME/.nimble/bin:$PATH"

# プロジェクトルート自動検出
find_project_root() {
    local dir="$PWD"
    while [ "$dir" != "/" ]; do
        if [ -f "$dir/niuv.toml" ]; then
            echo "$dir"
            return 0
        fi
        dir="${dir%/*}"
    done
    return 1
}

# プロジェクトルートに移動して実行
if PROJECT_ROOT=$(find_project_root); then
    cd "$PROJECT_ROOT"
fi

exec "/path/to/niuv" "$@"
```

## 🏗️ プロジェクト自動セットアップ機能 (`auto-setup`)

### 概要
プロジェクトの構造を自動検出してniuv.tomlを生成する機能です。

### 機能
- **プロジェクト種別自動検出**: Library/Application/Framework/Service/Tool
- **メインファイル自動検出**: プロジェクト名とファイル構造から判断
- **テストディレクトリ自動検出**: tests/test/spec/testingを自動発見
- **適切なタスク自動生成**: プロジェクト種別に応じたタスク

### 使用方法

```bash
# 現在のディレクトリを自動設定
niuv auto-setup

# 特定のディレクトリを自動設定
niuv auto-setup /path/to/project

# 既存設定を強制上書き
niuv auto-setup --force

# ヘルプ表示
niuv auto-setup --help
```

### プロジェクト種別の自動検出

| 種別 | 検出条件 | メインファイル | 追加タスク |
|------|----------|----------------|------------|
| **Framework** | `framework.nim`または`src/framework/`が存在 | `framework.nim` | examples, benchmark |
| **Service** | `service.nim`、`server.nim`、`api/`が存在 | `service.nim` | start, stop, status |
| **Tool** | `cli.nim`、`cmd.nim`、`tool.nim`が存在 | `cli.nim` | install, uninstall |
| **Application** | `main.nim`、`app.nim`が存在 | `main.nim` | run, debug, release |
| **Library** | 上記以外 | `{project_name}.nim` | examples, package |

### 自動生成されるniuv.toml例

**Libraryプロジェクトの場合:**
```toml
[package]
name = "my-library"
version = "0.1.0"

[build]
src_dir = "src"
main_file = "src/my_library.nim"
output_dir = ".build"

[test]
test_dirs = ["tests"]
test_pattern = "test_*.nim"

[tasks]
# Core build and test
build = "nim c -o:.build/my-library src/my_library.nim"
test = "cd tests && nim c -r test_all.nim"

# Quality assurance
clean = "find . -name 'nimcache' -type d -exec rm -rf {} + 2>/dev/null || true"
docs = "cd src && nim doc my_library.nim && mv *.html ../docs/api/ 2>/dev/null || true"

# Library specific
examples = "cd examples && find . -name '*.nim' -exec nim c -r {} \\;"
package = "nimble build"
```

## 📁 egison-patterns-miniでの実装例

egison-patterns-miniプロジェクトで実装されたPATH問題解決方法：

### 従来の問題
```bash
./setup_niuv_alias.sh: line 6: dirname: command not found
./setup_niuv_alias.sh: line 20: mkdir: command not found
```

### 解決方法
1. **汎用ライブラリ化**: `src/installation/auto_installer.nim`
2. **niuvコマンドに統合**: `niuv install-self`
3. **プロジェクト不要**: セットアップスクリプト削除

### 使用の流れ

```bash
# 1. niuvをビルド（一度だけ）
cd /path/to/GodsGolemInc/sources/libs/development-testing/niuv
nim c -d:release -o:~/.local/bin/niuv src/niuv.nim

# 2. 自動インストール（一度だけ）
niuv install-self

# 3. 任意のプロジェクトで使用
cd /path/to/any/project
niuv auto-setup         # niuv.toml自動生成
niuv init              # 環境初期化
niuv build             # ビルド
niuv test              # テスト
```

## 🌟 利用の利点

### 開発者体験の向上
- **設定レス**: プロジェクト側でのセットアップ不要
- **再利用可能**: 一度インストールすれば全プロジェクトで使用
- **堅牢性**: 環境依存の問題を自動解決

### プロジェクト管理の簡素化
- **不要ファイル削除**: tools/ディレクトリが不要
- **標準化**: 全プロジェクトで統一されたワークフロー
- **自動化**: 設定ファイルの手動作成不要

### エコシステム全体への影響
- **40+プロジェクト**: GodsGolemIncエコシステム全体で活用
- **一貫性**: 統一されたビルド・テスト体験
- **品質向上**: 自動化による人的エラーの削減

## 🚀 今後の拡張予定

### 予定されている機能
1. **テンプレートシステム**: カスタムプロジェクトテンプレート
2. **依存関係自動検出**: nimbleファイルからの依存関係読み込み
3. **CI/CD統合**: GitHub Actions、GitLab CIテンプレート生成
4. **パフォーマンス監視**: ビルド時間、テスト実行時間の追跡

### API拡張
```nim
# 将来的なAPI例
niuv.autoInstall(forceReinstall = false)
niuv.autoSetup(projectPath = ".", template = CustomTemplate)
niuv.generateCI(platform = GitHubActions)
```

この拡張により、niuvはCargoに匹敵する包括的なNim開発環境管理ツールとなります。
